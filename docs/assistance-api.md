# Assistance automobile — contrat d'API

> Modèle (corrigé) :
> 0. **Modèle d'OFFRES DE PRIX (style inDrive)** — remplace « le premier qui accepte prend la mission ». Plusieurs mécaniciens (validés, abonnés, disponibles) reçoivent la demande et font chacun une **offre de prix** (`POST /pro/offers/:id/bid`, révisable) ; la demande reste en `recherche` pendant la collecte ; le client **compare** (`bids` dans `GET /requests/:id`) et **valide** celle qu'il veut (`POST /requests/:id/bids/:offerId/select`, atomique). Le prix de l'offre retenue devient le montant convenu (`amountAgreed`). Valable pour les DEUX parcours.
> 1. **Deux parcours** selon la panne. Le client indique `immobilised` (booléen, défaut `true`) à la création / modification du brouillon. Immobilisée → `mode:"depannage"` (le mécanicien vient). Non immobilisée → `mode:"atelier"` : les garages proches font une offre et le client choisit celui où il se rend. **Double accord** : le garage s'engage en faisant son offre, le client valide en la choisissant → `visitStatus:"confirmee"` d'emblée (plus d'étape intermédiaire `proposee`, sauf affectation manuelle par l'admin : `aucune → proposee → confirmee`, ou `refusee` → retour en recherche).
> 2. **Tarifs** : `tariffs[service].indicatif` (clé conservée) est le « tarif affiché » (champ `tariff`, à titre de référence ; il initialise `amountAgreed` avant le choix). Après le choix, **montant convenu = prix de l'offre retenue + suppléments acceptés par le client** (pas de devis initial nécessaire ; tout devis proposé ensuite est un devis `supplementaire`). Sans offre (affectation admin) : somme des devis acceptés, sinon tarif.
> 3. **Paiement via le système (Jèko), jamais d'espèces.** DiagAssist ne facture rien au client mais prélève une **commission** (`commission_pct`, défaut 10, réglable 0..100 par l'admin) sur le paiement reçu par le mécanicien ; le net est « à reverser » (`payoutStatus`) puis marqué reversé par l'admin. Un paiement n'est jamais confirmé par le client : uniquement par webhook Jèko signé ou réconciliation serveur.
> 4. Seuls les mécaniciens validés ET abonnés (et disponibles) reçoivent les demandes et peuvent offrir (abonnement revérifié au moment du choix). Envoi simultané par vagues, analyse IA (`aiAnalysis`), invitation WhatsApp aux non abonnés (« une demande de dépannage près de vous, abonnez-vous pour faire une offre de prix », sans donnée privée).
> 5. **Cycle d'une proposition** (`assistance_offers.status`) : `envoyee` (à traiter, fenêtre `offer_timeout_s`, défaut 120 s) → `offre_faite` (offre envoyée, valable `bid_valid_s`, défaut 300 s) → `acceptee` (retenue) / `annulee` (autre choix, annulation, retrait) / `expiree` / `refusee`. Quand plus aucune proposition ni offre valide n'est ouverte, la vague suivante part (jusqu'à `max_candidates`) puis `sans_disponibilite` : jamais de blocage indéfini.

Toutes les routes renvoient `{ success: boolean, message?: string, ... }`. Les dates sont en millisecondes (epoch), les montants en entiers XOF.
Auth client / mécanicien : `Authorization: Bearer <auth_session_token>`. Auth admin : mêmes en-têtes que le reste de l'admin (`x-admin-code` ou session admin).
Si Postgres n'est pas configuré, toutes les routes `/api/assistance/*` répondent `503 { success:false, code:"ASSISTANCE_DB_MISSING", message }` (sauf `GET /api/assistance/status`).

## Statuts
- `status` (intervention) : `brouillon, recherche, affectee, en_route, sur_place, en_intervention, terminee, sans_disponibilite, annulee`
- `quoteStatus` : `aucun, propose, accepte, refuse` (`propose` tant qu'un devis attend l'accord du client)
- `mode` : `depannage, atelier` · `visitStatus` : `aucune, proposee, confirmee, refusee` (atelier uniquement) · `immobilised` : booléen
- `paymentStatus` : `aucun, en_attente, paye, echoue` · paiement `status` : `en_attente, paye, echoue, annule` · `payoutStatus` : `a_reverser, reverse`
- Pro `validationStatus` : `en_attente, valide, suspendu, refuse`
- Services (code) : `mecanique, electricite, diagnostic, batterie, pneumatiques, remorquage, vidange`

## Client
- `GET /api/assistance/status` → `{ enabled, dbConfigured, paymentConfigured, whatsappConfigured, services:[{code,label,description,available,proCount,availableNow,atelierAvailable,atelierProCount,atelierAvailableNow,tariff|null,indicativeAmount|null}], zones:[{id,name}], paymentMethods:["wave","orange","mtn","moov"] (vide si Jèko non configuré) }`. `available*` = dépannage (mécaniciens `mobile`/`both`) ; `atelier*` = garages (`garage`/`both` avec position connue).
- `POST /api/assistance/requests` body `{ service, vehicle:{brand?,model?,year?,engine?,source?:"catalogue"|"saisie"}, immobilised?:boolean (défaut true), symptoms, faultCodes?, description?, contactPhone, position:{lat,lng,accuracy?,source:"gps"|"carte"|"adresse",address?,landmark?,confirmed:true}, shareDiagnostic?:boolean, diagnostic?:{summary,faultCodes?,vehicle?}, mediaIds?:string[], submit?:boolean }` → `{ request }`. `submit:true` lance directement la recherche. `immobilised:false` → `mode:"atelier"`. Si le tarif du service est configuré, `amountAgreed` démarre à ce tarif. La position doit être `confirmed:true` pour passer en `recherche`.
- `PATCH /api/assistance/requests/:id` (brouillon seulement) mêmes champs.
- `POST /api/assistance/requests/:id/submit` · `/cancel {reason}` · `/retry` (depuis `sans_disponibilite`) · `/manual` (demande de prise en charge manuelle)
- `GET /api/assistance/requests` → `{ requests:[résumé] }` (historique du client)
- `POST /api/assistance/requests/:id/bids/:offerId/select` (client propriétaire, `:offerId` = `bids[].id`) : **choix atomique** (transaction + verrou de la demande + index unique d'affectation active). Effets : mécanicien affecté (`affectee`), `amountAgreed` = montant de l'offre, offre retenue `acceptee`, toutes les autres annulées, notifications (retenu : « Le client vous a choisi, X F CFA » ; autres : « Le client a choisi un autre mécanicien »). Atelier : `visitStatus:"confirmee"` d'emblée. Réponse : le détail client. Erreurs : 404 (demande/offre inconnue ou d'un autre client), 409 `NOT_SEARCHING` (demande plus en recherche, dont le 2ᵉ de deux /select simultanés), 409 `BID_EXPIRED` (offre expirée/annulée), 409 `SUBSCRIPTION_REQUIRED` / `PRO_UNAVAILABLE` / `PRO_BUSY` / `PRO_NOT_VALIDATED` (le mécanicien n'est plus éligible : son offre est retirée, le client en choisit une autre).
- `POST /api/assistance/requests/:id/visit` `{ accept:boolean }` (atelier, client propriétaire) : **ne sert plus qu'après une affectation manuelle de l'admin** (`visitStatus:"proposee"`). `true` → `confirmee` ; `false` → le pro est libéré et exclu, retour en `recherche` (`aucune`), nouvelle diffusion. Réponse : le détail client. Après un choix d'offre : 409 `NO_VISIT_PROPOSED` (déjà confirmé).
- `POST /api/assistance/requests/:id/leaving` (atelier, après confirmation) : « Je pars » → `en_route`. 409 `VISIT_NOT_CONFIRMED` sinon. Réponse : le détail client.
- `GET /api/assistance/requests/:id` → `{ request, pro|null, bids, quotes, payment|null, timeline, media, review|null, allowed:{cancel,retry,manual,pay,review,claim,decideQuote,selectBid,confirmVisit,leaving} }`
  - `bids` (uniquement en `recherche`, sinon `[]`) : offres **valides** (non expirées, non annulées), triées par prix croissant puis délai : `[{ id (à passer à /select), pro:{displayName, garageName, rating:{avg,count}|null, photoUrl:null (pas de photo gérée pour l'instant), specialties, trainings:[{title,issuer}] (vérifiées seulement), location?:{lat,lng,updatedAt} (ATELIER uniquement : position exacte du garage, réservée au client propriétaire)}, amount (XOF), etaMinutes, distanceKm, approximate:true, validUntil, isRevised, sentAt }]`. Jamais de téléphone du mécanicien avant le choix. `allowed.selectBid` = `recherche` ET au moins une offre. Une notification `nouvelle_offre` (« Nouvelle offre : X F CFA, arrive dans ~Y min ») est créée à chaque offre (et révision).
  - `request` : résumé commun `{ id, status, statusLabel, mode, immobilised, visitStatus, service, serviceLabel, tariff|null, vehicle, symptoms, quoteStatus, paymentStatus, amountAgreed, ... }`. `statusLabel` est adapté au mode (« Garage proposé », « Visite confirmée », « En route vers le garage », « Arrivé au garage »).
  - `payment` : `{ reference, method, amount, status, redirectUrl|null, updatedAt }|null` (jamais de commission côté client)
  - `pro` (après affectation) : `{ displayName, garageName, specialties, rating:{avg,count}|null, phone, trainings:[{title,issuer}], location:{lat,lng,updatedAt}|null, eta:{minutes,distanceKm,approximate:true}|null }`. En **atelier**, `location` est la position exacte du garage (dernière position partagée) et `eta` le trajet estimé du client jusqu'au garage (approximatif).
  - `timeline` : `[{ at, label, status }]` version client (sans données internes)
- `POST /api/assistance/media` body `{ requestId?, mime, dataBase64, name? }` → `{ media:{id,kind,mime,size} }` (images jpeg/png/webp ≤ 5 Mo, vidéo mp4/webm ≤ 8 Mo, audio webm/ogg/mp4/mpeg ≤ 5 Mo ; 8 fichiers max par demande). Sans `requestId` : média orphelin rattaché à la création (`mediaIds`).
- `GET /api/assistance/media/:id` (Bearer, ou `?token=`) → octets du fichier si le client est propriétaire, le mécanicien affecté ou admin.
- `GET|POST /api/assistance/requests/:id/messages` (`?since=<id>`) → `{ messages:[{id,fromRole:"client"|"pro",body,at}] }` ; POST `{ body }`.
- `POST /api/assistance/requests/:id/quotes/:quoteId/decision` `{ accept:boolean }` — accord enregistré (date + auteur).
- `POST /api/assistance/requests/:id/pay` `{ method:"wave"|"orange"|"mtn"|"moov", payerPhone? }` → `{ reference, redirectUrl, paymentStatus }`. Possible quand la mission est `terminee` et `amountAgreed>0`. Le montant est celui de la base (tout montant envoyé est ignoré). Jamais « payé » avant webhook signé Jèko / réconciliation. 503 `PAYMENT_NOT_CONFIGURED` si Jèko n'est pas configuré ; 409 si déjà payé.
- `GET /api/assistance/requests/:id/payment` → `{ payment, paymentStatus }` (rafraîchit auprès de Jèko si en attente)
- `POST /api/assistance/requests/:id/review` `{ rating:1..5, comment? }` · `POST /api/assistance/requests/:id/claims` `{ kind, message }`
- `GET /api/assistance/notifications` → `{ notifications:[{id,type,title,body,requestId,at,read}], unread }` · `POST /api/assistance/notifications/read` `{ ids? }`

## Mécanicien (`/api/assistance/pro/...`)
- `GET /pro/me` → `{ profile|null, directoryMatch:boolean }` ; `profile` = `{ phone, displayName, garageName, specialties, zoneIds, mobility:"mobile"|"garage"|"both", validationStatus, validationNote, available, shareLocation, location:{lat,lng,updatedAt}|null, trainings:[{id,title,issuer,completedOn,status}], documents:[{id,kind,label,status}], rating, missionsDone, activeMissionId|null, canReceiveMissions, blockers:[string] }`
- `PUT /pro/me` `{ displayName, garageName?, specialties:string[], zoneIds:number[], mobility }` (crée le profil en `en_attente` si absent)
- `POST /pro/documents` `{ kind, label, mime, dataBase64 }` (pdf/jpeg/png ≤ 4 Mo) · `POST /pro/trainings` `{ title, issuer, completedOn }` (déclaré, jamais affiché au client tant que non `verifiee`)
- `POST /pro/availability` `{ available:boolean, lat?, lng? }` (refusé si non `valide`)
- `POST /pro/location` `{ lat, lng, accuracy? }` (accepté seulement si disponible ou mission active ; sinon 409 pour arrêter le partage)
- `GET /pro/offers` → `{ offers:[{ id, requestId, mode, service, serviceLabel, vehicle, symptoms, aiAnalysis, status:"ouverte"|"offre_envoyee"|"retenue"|"non_retenue", canBid, tariff|null, range:{min,max}, myBid:{amount,etaMinutes,validUntil}|null, approxPosition:{lat,lng,radiusM}|null, distanceKm, expiresAt }] }`. `ouverte` = à traiter (`expiresAt` = fin de la fenêtre pour offrir) ; `offre_envoyee` = offre faite, en attente du choix (`expiresAt` = `myBid.validUntil`) ; `retenue` / `non_retenue` restent listées 30 min après le choix (`canBid:false`). `range` = fourchette acceptée : `tariffs[service].min/.max` ; à défaut 50 % / 150 % du tarif affiché (`indicatif`) arrondis ; sans réglage 1..500000. Dépannage : position arrondie ~1 km ; **atelier : `approxPosition:null`**, seule la distance est donnée ; jamais de repère ni de téléphone. Atelier : offres envoyées aux seuls mécaniciens `garage`/`both` avec position connue.
- `POST /pro/offers/:id/bid` `{ amount:int XOF, etaMinutes?:int 1..240 }` → `{ offer }` (même forme qu'une entrée de `GET /pro/offers`, `status:"offre_envoyee"`). Premier appel = offre ; appels suivants = **révision** (UPDATE, une seule ligne par proposition, la validité repart de `bid_valid_s`) tant que l'offre n'est ni retenue ni expirée. `etaMinutes` omis → ETA calculé et approximatif (dépannage : pro → client ; atelier : client → garage). Erreurs : 400 `BID_INVALID` (montant non entier, ETA hors 1..240), 400 `BID_OUT_OF_RANGE` (message avec la fourchette), 403 `SUBSCRIPTION_REQUIRED` / `NO_PRO_PROFILE` / `NOT_VALIDATED`, 404 (proposition d'un autre), 409 `ALREADY_TAKEN` (« le client a déjà choisi un autre mécanicien »), 409 `REQUEST_CLOSED` (demande annulée/close), 409 `OFFER_EXPIRED`, 409 `OFFER_CLOSED`, 409 `PRO_UNAVAILABLE` / `PRO_BUSY`. L'ancien `POST /pro/offers/:id/accept` n'existe plus (404).
- `POST /pro/offers/:id/decline` → décline la proposition (ou retire une offre déjà envoyée), `{ success }`.
- `GET /pro/missions` (toutes, pour missions + paiements) · `GET /pro/missions/:id` → détail `{ mission, quotes, media, messages, payment, tariffs, allowed }`. Dépannage : position exacte, repère et téléphone du client. **Atelier : `position:null` en permanence ; `clientPhone` et médias seulement après `visitStatus:"confirmee"` (acquis dès le choix du client)** ; `distanceKm` (distance annoncée à l'offre). `payment` : `{ reference, method, amount, status, commissionAmount, proAmount, payoutStatus, payoutAt }|null`. `allowed:{enRoute,surPlace,enIntervention,terminer,quote,release}` : en atelier `enRoute` est toujours faux (le client part) et rien n'avance avant confirmation
- `POST /pro/missions/:id/status` `{ to:"en_route"|"sur_place"|"en_intervention"|"terminee" }` — atelier : 409 `VISIT_NOT_CONFIRMED` tant que le client n'a pas confirmé, 409 `CLIENT_TRAVELS` pour `en_route` ; `sur_place` = client arrivé (permis directement depuis `affectee` si le client n'a pas appuyé sur « Je pars »). `en_intervention` n'exige aucun devis initial quand un prix est convenu (offre retenue) ; `terminee` fixe le montant (prix de l'offre + suppléments acceptés ; sans offre : devis acceptés, sinon tarif) · `/release {reason}` (désistement) · `/diagnosis {text}`
- `POST /pro/missions/:id/quotes` (avec un prix d'offre convenu, `kind` est forcé à `supplementaire` et soumis à l'accord du client ; un supplément refusé ne change pas le prix) `{ kind:"initial"|"supplementaire", lines:[{kind:"deplacement"|"diagnostic"|"main_oeuvre"|"pieces",label,amount}], note? }`
- `GET /pro/earnings` → `{ paid (net total payé), toReceive (payé, pas encore reversé), received (reversé), commissionPct, payments:[{reference,requestId,service,serviceLabel,method,status,grossAmount,amount,commissionAmount,proAmount,payoutStatus,payoutAt,createdAt}] }`
- `GET /api/assistance/tariffs` → `{ tariffs:{ [service]:{deplacement?,diagnostic?,indicatif?,min?,max?} }, currency:"XOF" }` (`indicatif` = tarif affiché ; `min`/`max` = fourchette des offres ; valeurs configurées par l'admin)

## Admin (`/api/admin/assistance/...`)
- `GET /dashboard` → indicateurs réels (demandes reçues, acceptées, terminées, délais moyens d'acceptation / d'arrivée, pros par statut ; `payments:{collected,pending,commission,toReverse,reversed,paidCount,toReverseCount,commissionPct}` = encaissé via Jèko, commissions DiagAssist, net à reverser / déjà reversé ; `atelierRequests`)
- `GET /requests?status=&zoneId=&service=&from=&to=&manual=1` · `GET /requests/:id` (détail + chronologie complète + offres + messages) · `POST /requests/:id/assign {proPhone}` (annule les offres, `amountAgreed` = tarif affiché ; atelier : visite `proposee` à confirmer par le client) · `/redispatch` · `/cancel {reason}`
- `GET /pros?status=` · `POST /pros/:phone/validate|suspend|refuse {note?}` · `POST /pros/validate-directory` (valide tous les profils issus de l'annuaire en attente) · `PATCH /pros/:phone {specialties, zoneIds, mobility}` · `GET /pros/:phone/documents/:id` (fichier) · `POST /pros/:phone/documents/:id/verify {status}` · `POST /pros/:phone/trainings {title,issuer,completedOn,status}` · `POST /trainings/:id/verify {status}`
- `GET|POST|PATCH|DELETE /zones` · `GET /services` · `PATCH /services/:code {enabled,label}` · `GET|PUT /settings` (offer_timeout_s 10..600 défaut 120 = fenêtre pour offrir, `bid_valid_s` 30..3600 défaut 300 = validité d'une offre, search_radius_km, broadcast_size, max_candidates, location_max_age_min, avg_speed_kmh, `commission_pct` 0..100 défaut 10, `tariffs[service]` = `{ indicatif (tarif affiché), min, max (fourchette des offres), deplacement, diagnostic }` entiers 0..1 000 000, `min ≤ max` sinon 400 ; le champ `tariffs` remplace l'ensemble des tarifs)
- `GET /payments` → `{ payments:[{reference,request_id,payer_phone,pro_phone,pro_name,method,amount,commission_pct,commission_amount,pro_amount,status,payout_status,payout_at,payout_by,created_at,updated_at}] }` · `POST /payments/:reference/payout` (marque le net reversé au mécanicien, une seule fois ; 409 sinon) · `POST /payments/:reference/reconcile` (interroge Jèko) · `GET /requests/:id` inclut aussi `payments` · `GET /claims` · `POST /claims/:id/resolve {note}` · `POST /sync-directory`

## Webhook Jèko
`POST` du webhook de paiement existant (signature HMAC vérifiée par `jeko.routes`) : les références `dgas-…` sont déléguées au module (`onExternalWebhook`). Montant (×100) et identifiant Jèko contrôlés ; traitement idempotent (un webhook rejoué ne change rien). À la confirmation : `commission_amount = round(montant × commission_pct / 100)`, `pro_amount = montant − commission`, `payout_status = a_reverser`. Un second règlement sur une mission déjà payée est enregistré sans commission ni reversement (événement `double_paiement_detecte`, à rembourser).
